# CLAUDE.md — Эхо Подземелья: Vertical Slice

Этот файл — обязательный контекст проекта. Следуй ему строго при любой задаче в этом репозитории.

## Что мы строим

Вертикальный срез roguelite-игры: система дверей (3 состояния) + AP-бой. Цель — проверить, залипателен ли core loop, НЕ полная игра.

## Жёсткие границы scope (не выходить за них без явного запроса)

**Входит:**
- Двери: 3 состояния (Locked, Unstable, Echo) + 2 триггера (Lost, Abandoned)
- Бой: Action Points с cooldown-компромиссом скорость/точность/крит, энергия только от киллов, Adrenaline-механика (урон без смерти 3 сек → +15% скорость, быстрее падает HP)
- Прогон: 5 уровней подряд → награда → мини-Хаб (только «начать новый прогон» + статистика сессии) → новый прогон
- Один играбельный класс: Воин. Никаких других классов.
- Desktop-only ввод (клавиатура/мышь). Мобильный ввод НЕ реализуем.
- Ассеты: используем спрайты Kenney.nl как заглушки, автор параллельно рисует кастомные — структурируй код так, чтобы замена спрайта была тривиальной (без хардкода путей в логике).

**НЕ входит — не реализовывать, даже если кажется что "заодно можно":**
- Мета-прогрессия (Осколки Души, дерево навыков, перманентные бонусы)
- Монетизация, магазин скинов, премиум-валюта
- Другие классы, кроме Воина
- Мобильные жесты, тач-контролы
- Звук/музыка (тишина или пустые заглушки)
- Сохранение между сессиями/пользователями, аккаунты, backend, БД
- CRT/scanline визуальные эффекты

Если задача явно требует выйти за эти границы — остановись и спроси, а не расширяй scope молча.

## Стек

- **Phaser.js 3 + TypeScript**, сборка через Vite
- Деплой: Netlify/Vercel (уже подключены к GitHub-репозиторию)
- Без бэкенда и БД на этом этапе — всё состояние живёт в памяти игровой сессии (JS-объекты), персистентности не нужно

## Конвенции кода

- Строгий TypeScript (`strict: true`), никаких `any` без явной причины
- Состояния дверей и триггеры — `enum`, не строки
- Формулы боя (AP, крит, скорость атаки) выносить в отдельный модуль (`combat/formulas.ts`), не размазывать по сценам
- Каждая Phaser Scene отвечает за один экран/этап (Hub, Run, Combat overlay) — не смешивать логику
- Простая, читаемая структура важнее преждевременной оптимизации — это прототип для проверки fun-фактора, не продакшн-код на миллион пользователей

## Структура репозитория (целевая)

```
src/
  scenes/        # HubScene, RunScene, CombatScene
  entities/      # Player, Enemy, Door
  combat/        # formulas.ts, AttackSystem.ts, AdrenalineSystem.ts
  dungeon/       # LevelGenerator.ts, DoorStateMachine.ts
  data/          # enums, типы, константы
  assets/        # Kenney-спрайты (заглушки)
```

## Как работать над задачами

- Бери одну задачу из бэклога за раз, не пытайся сделать несколько сразу
- Перед реализацией сложного куска (генератор уровней, боевая система) — сначала план, потом код
- После каждой задачи — краткое summary, что сделано и что осталось
